## Deferred observations (non-blocking)

1. **Inherited-row same-string selection no longer pins**: when the displayed model comes from inheritance (a project row without a local override, or a global row falling back to the top-level `model` key), selecting that same string is treated as a no-op and does **not** create the explicit `agents.<id>.model` override that V1 would have written. The effective model is identical, so nothing visibly changes, but the latent semantics differ: a later global change now propagates instead of being blocked by a pinned override. In that path there would be no variant to strip (the write creates a fresh entry), so a `!inherited` refinement of the no-op guard would also be safe — but skipping is the conservative direction (fewer writes) and matches the Task 3 item's "unchanged selections" wording. Also, in this untested path the success toast says "Kiki-Modell gespeichert" although nothing was written (copy-accurate for the effective model, but technically a no-op). Task 10/11 PTY acceptance may want to pin the intended semantics.
2. **Report evidence nit — audit not re-run by implementer**: the report's security section documents boundaries but does not itself record a fresh `npm audit` run. Per the Task 8 precedent (no `package.json`/`package-lock.json` change → no fresh audit required) this is acceptable; the reviewer ran it: 0 high, 0 critical, 32 moderate — identical to the Task 8-reviewed graph. No action needed.
3. **Test-name nuance**: the second half of `prevents duplicate saves while pending and after a successful save` actually exercises the new no-op path (the deferred first save never mutates the fixture row, so re-selecting `provider/beta` is skipped rather than saved). The assertion correctly pins the new behavior (it would fail under V1 semantics); only the name slightly understates what is verified. Immaterial.
4. **Interim entrypoint**: `src/tui/index.ts` still imports the retired V1 SDK and passes the old V1 api object to `registerKikiMenu` — the sole cause of the two tsc diagnostics and the release-suite setup failure, owned by Task 10, untouched here. Accurately deferred; actual packaged PTY/provider-counter acceptance for `/kiki` remains Tasks 10/11 (mock-only proof in Task 9 is by design).
