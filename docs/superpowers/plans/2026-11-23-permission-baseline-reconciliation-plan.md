# Permission Baseline Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Architect review precedes implementation; final independent review follows implementation.

**Goal:** Refresh global defaults by exact rule identity while preserving machine customs, deleting ownership hashes and state machinery rather than replacing them.

**Architecture:** Classify each source rule against the role-specific union of existing historical defaults and the fresh baseline. Persist the fresh baseline prefix, stable exact-deduplicated customs, then the existing secret-edit tail through the existing verified transaction. No new persistence, dependencies, evaluator, wrapper layer, or override route.

**Tech Stack:** TypeScript/Node ESM, existing JSONC/YAML utilities, Vitest; tracked `dist` generated by `tsc`.

**Spec:** User-approved conversational requirements supplied with this task (“go!”); registry task `permission-baseline-reconciliation`, `.agentic/kiki/TASK_REGISTRY.json:4–13`. This conversation supersedes historical full-array ownership and shape-blocking requirements; do not rewrite historical approved specs.

## Global Constraints

- “Never hardcode secrets in source code.” “Use parameterized statements for every database query.” “Never leak internal stack traces in API responses.” Source: `.agentic/kiki/alignment.json`; this change introduces neither database access nor API responses.
- Exact identity is `(action, resource, effect)`; an identical known default is a default regardless of author or array position.
- Unknown to both old and fresh defaults means custom: preserve every effect, without new collision warnings or overlap evaluation.
- Remove ownership hashes AND all state read/write/publication/invalidation/state-specific rollback; existing state is inert, not migrated or deleted.
- Preserve generator safeguards, native ordering, independent backups, config verification, rollback, malformed-input checks and project-only permissions CLI boundaries.
- No installed/global configuration writes, live update, delegation, commits or publishing are authorized. Preserve dirty user changes; do not edit the registry or existing analysis report.

## Review Focus

1. Old defaults interleaved with customs must retire even when no complete historical sequence remains (Task 1).
2. Same action/resource with a different effect is a distinct identity; unknown denies and differing custom effects must survive in stable order (Tasks 1–2).
3. Reordered, truncated and repeated known defaults must not be mistaken for customs or ambiguous ownership (Task 1).
4. Legacy state, including corrupt state, must neither gate updates nor be read, written, backed up or invalidated (Task 2).
5. Catchable write/verification failure must still restore config/markdown; incomplete restoration must identify backup recovery without ownership-state claims (Task 2).
